# 当日时间分配图

Status: implemented

历史页点日历格子后，日历下方出现当日番茄圆点和当日时间树图。本特性在树图**上方**加一张 24 小时时间轴，显示这一天哪些时段跑着番茄钟；计时页的「今日统计」里同样出现在时间树图上方。

参考形状：一条基线、每小时一根刻度、块按真实时段浮在基线上方、标签在刻度上方。块按项目着色，可 hover 看具体时段，可点击打开桑基图（与番茄圆点同一入口）。

## 决策

| 项 | 结论 |
| --- | --- |
| 位置 | 历史页：日期+圆点那一行之下、`TimeTreemap` 之上（`History.tsx`）。计时页：`timer.stats.timeSpent` 标题之下、`PomodoroTimeTreemap` 之上（`Timer.tsx`） |
| 两种模式 | **选中日期**：这一天每个番茄一块，按项目着色。**未选日期**：整个筛选范围（年 / 月 / All time）按一天里的时候聚合，画成面积图。两种模式共用同一个盒子，所以切换时下面的图不移动 |
| 显示条件 | 历史页**一直占位**：盒子固定高度，没数据时只留空盒子（和圆点行同一思路）。计时页只有日期模式 |
| 数据 | 日期模式吃已有的 `PomodoroRecord[]`（历史页 `shownPomodoros`，计时页 `state.pomodorosToday`）；范围模式吃 `aggInfo.timeOfDay`，由 worker 的 `aggHistory` 一并算出。**不新增查询、不新增 IPC** |
| 横轴 | 固定 0:00–24:00，不随活动区间裁剪 |
| 刻度 | 坐标横轴形态：整点刻度 4px、半小时刻度 2px，同色，都从轴**向上**伸进绘图区；**时间标签在轴下方**；0:00 与 24:00 不带刻度，轴右端画箭头 |
| 标签密度 | 按实测宽度自适应，见下「宽度与刻度」。始终含 `00:00` 与 `24:00` |
| 块的位置 | 左边缘 = 起始时刻，宽度 = 时长；相邻块之间 1px 页面色缝（与树图一致） |
| 块的颜色 | 项目色，来自共享映射（见下「项目配色」） |
| 交互 | 日期模式：hover 出 `Hint kind="live"`，点击 = `chooseRecord(record)`，与圆点同一个入口，键盘可聚焦。范围模式只读：每个非空半小时一根 hover 提示，不可点 |
| 命中区 | 日期模式：按钮就是色块本身，横向不外扩（空档里悬停与点击都不响应），纵向比色块上下各多 5px。范围模式：每个非空半小时**整列**（从轴到绘图区顶部）都是提示区，见下 |
| 今天 | 日期模式下，选中日期等于今天时画一条当前时刻竖线（`--pl-primary`）。范围模式不画——那是多天叠加出来的形状，没有「现在」 |
| 实现形态 | HTML 绝对定位，`left`/`width` 用百分比；范围模式的面积用一层 SVG 画（阶梯路径，见下）。不接 `width` prop，组件自己量宽度。历史页用一层与 `calendarWidth` 同宽的容器夹住它，计时页撑满 `MoreInfo` |
| 宽度参考 | 历史页 670–1000px（`History.tsx` 的 `calendarWidth`），计时页 ≤850px。350px 那种故意拉小的窗口不在支持范围 |

### 为什么是 HTML 而不是 SVG

块要可点击、要有焦点环、要挂 `Hint`。用真 `<button>` + 百分比定位，三样都是白拿的，而且窗口 resize 时布局自动跟随，不需要按宽度重算坐标。`GridCalendar` 的 SVG 写法在这里只剩「坐标换算」的成本，没有收益。

## 宽度与刻度

每小时像素 = 宽度 / 24；670px → 27.9，1000px → 41.7。标签宽度约 30px，所以：

> 标签步长取 `{1, 2, 3, 4, 6}` 中满足 `步长 × 每小时像素 ≥ 60` 的最小值。

| 宽度 | 每小时 | 标签间隔 | 步长 |
| --- | --- | --- | --- |
| 1000 | 41.7 | 83 | 2h |
| 850 | 35.4 | 71 | 2h |
| 670 | 27.9 | 84 | 3h |

两端标签分别用 `start` / `end` 锚点，中间居中，避免 `00:00` 和 `24:00` 被裁掉——这样也不用给绘图区加内边距（加了会让块相对真实时刻偏移半个标签宽）。

半小时短刻度在 670px 下间距 14px，作为基线旁的 3px 小刻度是正常刻度尺密度，不设阈值。

## 项目配色

现状没有稳定的「项目 → 颜色」映射：树图按 `projectData` 的排序上色（`TimeTreemap.tsx` 的 `levels.color`），排名一变颜色就变；桑基图那边是 `ColorEncoder.getAColor()` 随机取色。两张图放在一起会互相矛盾。

新增共享映射 `src/components/Visualization/projectColors.ts`：

- 取 `boards`，按 `createdTime` 升序（相同时按名字）排序，依次取 `tokens.treemapColors` 的槽位，得到「项目名 → 颜色」；
- key 用**项目名**：树图的 `projectData` 只有名字（`aggPomodoro.ts` 已把 boardId 解析成名字），用 boardId 做 key 两边无法共用；
- 新增看板只会追加到队尾，已有项目的颜色不变；超过调色板长度就循环；
- 未归属（无 `boardId`）与看板已删除的会话落到 `--pl-text-tertiary` 灰，和树图里的 `Unknown` 桶同义。
- `TimeTreemap` 改为给每个项目块指定 `itemStyle.color`（`levels` 保留给应用面板与兜底）。

已知取舍：两个同名看板得到同一个颜色——它们在树图里本来也已经同名。调色板只有 9 色，第 10 个看板会和第 1 个同色。没有传 `boards` 时树图仍按顺序上色（`levels` 兜底），时间轴则全部落到中性色。

## 视觉细节（截图校对过）

- 形态是坐标横轴，不是尺子：刻度从轴向上伸进绘图区，标签在轴下方，两条信息各占一侧，不再挤在同一条带上；轴右端以箭头收尾，没有 0:00 / 24:00 两根收口刻度。
- 刻度画在图层**之后**：它指向绘图区内部，必须压在面积填充之上才看得见。被色块或面积盖住的那几段里，刻度会融进色块的 1px 描边或浅填充里——空档处清楚，有数据处很淡；这是「把 4px 让给绘图区」的代价，不是 bug。
- 画在图层之上的东西（轴、两种刻度、箭头、当前时刻线）都带 `pointer-events: none`：1px 宽的刻度正好压在块或桶列上，会吞掉本该由它们回应的悬停，扫过整点时时提示会闪一下。
- 日间调色板末尾是近白色（`#ffffc2`），12px 高的块在 `#f5f5f5` 上几乎看不见。块加 1px inset 描边 `var(--pl-text-tertiary)`；夜间主题下这条描边是 35% 白，深紫、深蓝块靠它才和 `#1f1f1f` 分开。
- 轴、整点刻度、半小时刻度、箭头同色（`--pl-text-tertiary`）：坐标轴只有一条线，刻度再分深浅会读成两套东西。
- 纵向排布（自上而下）：块 0–12、空隙 2、刻度 14–18（半小时 16–18）、轴 18–20、标签 24–38，整图 38px 高。
- 刻度占的那 4px 属于**绘图区**，不再单独占轴下方的一条带：范围模式的面积图因此从 14px 长到 18px，而不是把整条轴再撑高 4px。刻度和色块之间仍有 2px 空隙。
- 箭头 4px 宽、4px 高，画在容器右侧外 4px，所以轴端（24:00）之后还有一小截，像数轴的开口。
- 「当前时刻」线只覆盖块行到轴底（0–20），不穿进标签行。

## 范围模式：一天里的时间分布

- 数据来自 `getTimeOfDayHistogram`（`src/utils/aggPomodoro.ts`）：每 30 分钟一个桶，共 48 个，值是桶内的专注小时数。`aggHistory` 用**和树图同一批 `period` 记录**算，所以横轴和树图永远描述同一个范围。
- 一个番茄按重叠切进多个桶：10:50–11:15 给 10:30 桶 10 分钟、给 11:00 桶 15 分钟；跨午夜的会话喂给同一条轴上 0 点后的桶，不丢弃也不翻倍。
- 口径是**时长**而不是番茄个数：25+5 的节奏会让「开始次数」每半小时出现一次尖峰，那个形状说明的是节奏，不是时间分配。
- 画法是阶梯面积（`histogramAreaPath`）：每个桶是一段等高的平台，峰值不会被抹成缓坡；填充 `--pl-primary` 22%，顶边 1px 同色描边。
- 绘图区 18px（整图 38px），读起来仍像一条丝带，但足够看出高低。要更好读就得把整条轴加高——两种模式必须一起改，不能只放大这一种。
- 每个非空桶上面盖一个透明 HTML 列承载 `Hint`。这一列从轴到绘图区顶部整列可命中，不是只覆盖填充到的高度：柱子表达的是一个时间**类别**的数值，类别带是整列（和直角坐标的 band 轴一样），空着的那半个桶仍然属于这个桶。提示内容是 `10:30–11:00 · 1.2 小时`。不要用 SVG `<rect>`：`Hint` 要克隆事件的元素必须是 HTML，`rect` 在 jsdom 与真实渲染里都会被当成未知标签。
- 整图 `role="img"`，概括是 `42.5 小时 · 最集中在 10:00–11:00`；不可点，也不进 tab 顺序。

## 时长口径

块右边缘 = `startTime + spentTimeInHour`。

`spentTimeInHour` 是名义专注时长（`Timer.tsx` 写入 `focusDuration / 3600`，rotten 会话写实际经过时长），不是墙钟跨度：中途暂停过的番茄，实际占用比这个长，块会显得比真实区间短。记录里没有 `endTime`，老记录也可能没有 `stayTimeInSecond`，逐个还原代价大于收益，所以接受这个近似——它和树图、圆点旁的小时数同一口径。

## 边界情况

- **空记录**：不画轴，只保留同样高度的空盒子（`aria-hidden`，不向辅助技术暴露任何角色）。历史页无条件挂载它，所以选日期、加载中、空日、切日期都不会移动下面的图；范围模式里整个筛选范围都没有记录时也一样；
- **跨午夜**：`startTime` 属于当天、结束落到第二天 00:15 的番茄，在 24:00 处裁掉，不画到画布外；
- **`spentTimeInHour <= 0`**：跳过，不画零宽块；
- **时段重叠**（数据异常，比如手工编辑过）：两块按各自真实区间绘制，DOM 顺序后者盖住前者，不做特殊处理；
- **今天之外的日期**：不画当前时刻线。

## 可访问性

- 每个块是 `<button type="button">`，带 `data-pressable`（拿全局焦点环），`aria-label` 与 Hint 文案同文：`项目 · 14:05–14:30 · 25 分钟`；
- 整图带 `role="img"` 与一句概括（`5 个番茄 · 09:00–18:00`），块不可聚焦时（如无 `onChooseRecord`）键盘用户仍能读到当天概览；
- 块不可点击时（没有 `onChooseRecord`）退化为普通 `div`，不冒充按钮。

## 测试

纯函数（`ProjectTimeline.tsx` 导出）：

- `labelStepFor(width)`：相邻标签间距 ≥ `MIN_LABEL_GAP`，且越窄步长越大；
- `buildSegments(records)`：投影到 0–24、按起始时间排序、跨午夜裁到 24、跳过零时长；
- `histogramAreaPath(values, peak)`：峰值桶是一段等高平台，不是斜线；
- `formatClock`：按分钟取整，1440 分钟打印成 `24:00`。

`getTimeOfDayHistogram(records)`（`src/utils/aggPomodoro.ts`）：跨桶切分（10:50–11:15 → 10 分钟 + 15 分钟）、总和不重不漏、跨午夜落到 0 点后的桶。

`createProjectColorOf(boards, tokens)`：新增看板不动旧颜色、与 map 的插入顺序无关、未归属落到中性色、同名看板不占两个槽位、跟随主题调色板。

组件：

- 渲染出与记录数相同的按钮，`aria-label` 含项目名与起止时间；
- 点击某个块回调拿到的是那条记录（不是紧邻的那条）；
- 没有记录时不画轴、不暴露按钮或图表角色（只留占位的空盒子）；
- 没有 `onChooseRecord` 时不渲染按钮，整图退化为 `role="img"` 的概括；
- 给了 `timeOfDay` 时画范围模式：没有按钮，`role="img"` 的概括是「4.0 小时 · 最集中在 09:00–12:00」；
- 范围全是零时同样只留空盒子。

`TimeTreemap`：同一项目在排名互换后颜色不变（旧实现按顺序上色会挂）。

当前时刻线不测：它没有文案也不可聚焦，任何能在 jsdom 里断言它的写法都会落到属性/类名上。改动那一行后靠肉眼在「今天」的日期上确认。

横向命中区同理不测：按钮不再外扩，`left`/`width` 就是块的起止时刻，而 jsdom 没有布局也没有 hit-testing，能断言的只有内联样式。靠肉眼确认「在两个番茄之间的大空档里悬停不弹提示、点击无反应」。

宽度对齐（历史页与树图同宽）同理不测：jsdom 没有布局，`clientWidth` 恒为 0，任何断言都只能检查容器上的内联宽度，钉的是实现。

## 待做

以下一条已确认要做，具体做法留到动手时再定。

1. **跨 24:00 的最后一块，提示里的时间与时长不对。**
   `buildSegments` 把 `endHour` 裁到 24，而 aria-label 的起止时间和时长都按裁剪后的值算，于是 23:50 开始、00:15 结束的番茄显示成 `23:50–24:00 · 10 分钟`。
   方向：segment 保留真实结束时刻（可以大于 24）供文案使用，只在算宽度时裁剪；时间显示取 00:15 还是 24:15 待定，倾向 00:15（下一个自然日）。用例断言跨午夜那条的 aria-label 是 `23:50–00:15 · 25 分钟`。

## 不含

- 不做横向滚动、缩放、图例；
- 不在历史页未选日期时展示整段时间的分布（这是另一个语义，本次不做）；
- 不改圆点行、树图、词云。
