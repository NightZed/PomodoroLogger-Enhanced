# 看板 / 列表 / 卡片：删除、隐藏与会话归属

Status: draft（设计已定，实现未开始）

## 背景

现在的删除只删自己那一行，不清理引用：

- 删卡片：`move` 行全留，导入时每次报「移动记录将被丢弃」却从来不丢；
- 删列表：列表里的卡片只失去 `list.cards` 引用，变成孤儿卡，导入时报「卡片 xxx 将被移除」却也从来不删；
- 删看板：`lists`、`cards`、`move` 整棵子树残留，UI 不可见但每次导出都带着。

两种警告都只报警不动数据，所以是每次导入都会重播的固定干扰项。

另外，番茄会话有两个归属维度，但只有「项目缺失」在界面上可见（历史页的 `Unknown`）；「有项目但没有挂到任何卡片」完全不可见。

## 目标

1. 删除是真删除：级联、单事务、可预期。
2. 看板提供「隐藏」作为一种可逆的软删除。
3. 番茄记录提供按天管理：改项目、删除。
4. 让「未挂卡片的会话」可被发现和定位。

## 非目标

- 不做回收站/撤销。
- 不改变「番茄结束时自动挂到 focusedList 所有卡片」的现有行为。
- 不删除 `sessions` 记录（除非用户显式删除单条会话）。

## 决策摘要

| 项           | 结论                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------- |
| 删除语义     | 真删，级联，单事务                                                                       |
| 番茄记录     | 不随卡片/列表/看板删除消失                                                               |
| 卡片引用     | 改项目或删记录时自动解绑并扣减卡片时长                                                   |
| 非空列表     | 级联删卡，确认框说明数量                                                                 |
| 看板删除     | 允许，提示记录会变成 `Unknown`；同一弹窗提供隐藏开关                                     |
| 隐藏入口     | 看板编辑弹窗顶部                                                                         |
| 隐藏筛选     | Kanban 首页右上角，与「看板/表格」切换并列的 Segmented「活跃 / 已隐藏」                  |
| 历史维度     | 隐藏看板在历史页的项目筛选中保留，标注「已隐藏」                                         |
| 会话管理入口 | History 点某天 → 日期条上的「管理」 → 弹窗                                               |
| 未挂卡定位   | 按天弹窗的「卡片」列 + 筛选；看板页「未分配番茄」面板；两处都能点圆点看桑基图；首页不加角标 |
| 批量挂卡     | 支持，移动语义：先从其他卡片解绑，再挂到目标卡                                           |
| 番茄归属     | 一番茄一卡：focusedList 只有一张卡时自动挂；多张时在结束遮罩上选（默认第一张，可选不挂） |

## 数据模型

`KanbanBoard` 增加 `hidden?: boolean`（默认 `false`）。

- `src/renderer/components/Kanban/type.d.ts`：加字段。
- `src/main/db/schema.ts`：`boardSpec.fields` 加一列 `hidden`，同时加进 `boards` 建表语句。
  `createSchema` 已有 `ALTER TABLE ... ADD COLUMN` 的补列逻辑（`schema.ts:212-226`），旧库自动升级，不需要版本迁移。
- 导出/导入：`hidden` 随 `doc` 列自动携带，无需改校验器。
- 合并语义：**已存在的看板保留本地的 `hidden`**；本地没有的看板采用文件中的值。理由是隐藏属于本地视图偏好，不应被一次导入重置。
  若日后需要「文件优先」，在 `mergeBoard` 的 `lastVisitTime` 分支里补一行即可。
- 读取时统一 `!!hidden` 归一化，不校验类型（错类型最多退化成可见，不值得拒绝整个导入文件）。

## 删除

### 命令

主进程新增一条事务命令 `deleteKanbanItems({ cards?, lists?, boards? })`，在一次 `runInTransaction` 里：

1. 展开净集合：
   - `boards` → 该板的所有 `lists`
   - `lists` → 每个 list 的 `cards`
2. 删除 `cards`、`lists`、`boards`，以及相关 `moves`（`cardId` 命中，或 `fromListId` / `toListId` 命中）。
3. 更新仍存在的列表：从 `cards` 数组移除被删卡片。
4. 更新仍存在的看板：只把被删除的列表从 `lists` 里去掉。
   `spentHours` / `relatedSessions` 是**会话级**汇总（这个项目的番茄），删卡只是让那些会话变成「未挂卡」，项目的总时长与番茄数不变。
   早期实现会扣减被删卡片的 `actual` 并从 `relatedSessions` 里摘掉「仅被该卡引用」的会话，结果删卡一次，看板总时长和番茄数一起变少，而历史页仍把这些记录算在这个项目上。
5. 返回实际删除的 id 与受影响列表/看板的最终状态，渲染层一次 `applyKanbanDeletion` 覆盖三个 slice。

### 级联表

| 输入     | 一起删除                                         | 不动                                          |
| -------- | ------------------------------------------------ | --------------------------------------------- |
| `cards`  | 卡片行、`moves(cardId)`                          | `sessions`（`boardId` 不变）                  |
| `lists`  | 列表行、列表内卡片、这些卡片的 `moves`           | `sessions`（`boardId` 不变）                  |
| `boards` | 看板行、其所有列表、这些列表的卡片、相关 `moves` | `sessions`（`boardId` 悬空 → 历史 `Unknown`） |

### 渲染层

`deleteCard` / `deleteList` / `deleteBoard` 保留现有签名，内部改为调用新命令再 dispatch。
`List.tsx` 现有的「focused / done 列表不能删」限制保留。

删除当前聚焦的看板：清空 `timer.boardId`。若正在计时，提示「本次会话将记为无项目」（`Timer.tsx:987-995` 已有兜底，不会崩）。

### 确认文案

- 卡片：「卡片和它的 N 条移动记录会删除；它的 M 个番茄记录会保留在历史中。」
- 列表：「列表里的 N 张卡片会一起删除。」
- 看板：「X 张卡片、Y 个番茄记录；删除后这些番茄会在历史中显示为 Unknown。」

## 隐藏

### 入口

- 看板编辑弹窗顶部一个「隐藏此看板」开关（仅编辑态显示，新建态不显示）。
- 删除按钮仍在弹窗底部，与隐藏开关同屏，便于用户改主意。

### 筛选

- Kanban 首页右上角，与「看板 / 表格」视图切换并列，放 Segmented「活跃 | 已隐藏 (N)」。
- 切到「已隐藏」时只显示隐藏看板，卡片灰化，可进入、编辑、取消隐藏、删除。
- 隐藏看板参与排序时排在已隐藏组内，`pin` 仍在组内置顶。

### 生效点

- `FocusSelector`（`Timer/FocusSelector.tsx:37`）：过滤 hidden。
- 当前 `timer.boardId` 指向刚隐藏的板：清空并 toast 提示。
- 历史页项目筛选：保留，名称后加「（已隐藏）」。
- 看板概览统计与排序：默认排除隐藏板。
- 隐藏板仍计入历史项目名解析，因此不会变成 `Unknown`。

## 番茄会话的两种归属

- **项目归属**：`sessions.boardId`。缺失或悬空时，历史页聚合为 `Unknown`。
- **卡片归属**：由 `card.sessionIds` 反向引用，会话本身没有字段。一个会话可以被多张卡片引用（番茄结束时会把会话挂到 focusedList 里的**每一张**卡片，见 `Board/action.ts:511-525`）。

状态推导：

| 状态           | 条件                                            | 界面表现                               |
| -------------- | ----------------------------------------------- | -------------------------------------- |
| 正常           | `boardId` 有效，且被至少一张卡引用              | 无                                     |
| 有项目、未挂卡 | `boardId` 有效，但不在任何 `card.sessionIds` 中 | 目前**不可见**                         |
| 无项目         | `boardId` 缺失或指向不存在的看板                | 历史页 `Unknown`；导入日志 `unknown=N` |

删除操作对两种归属的影响：

| 操作                                  | 项目归属             | 卡片归属 |
| ------------------------------------- | -------------------- | -------- |
| 删卡片                                | 保留                 | 失去     |
| 删列表（级联删卡）                    | 保留                 | 失去     |
| 删看板                                | 失去（变 `Unknown`） | 失去     |
| 项目聚焦但没有卡 / `focusedList` 为空 | 保留                 | 从未获得 |

### 看板总览的口径

总览卡片与表格里的「已花时间」读 `board.spentHours`，不是卡片 `actual` 之和：未挂卡的番茄（以及卡片被删后留下的番茄）仍然属于这个项目，只是在卡片上找不到。番茄数一直读 `relatedSessions.length`，所以它从来是对的——两者口径不一致时，表现就是「番茄数对、时长少」。

- 剩余估算（`estimatedLeftTimeSum`）仍按卡片求和：估算写在卡片上，未挂卡的会话没有估算。
- 排序里的「已花时间」本来就读 `spentHours`，因此修完之后显示与排序才是同一个数。
- 删除卡片只改归属，不减看板的总时长与番茄数（见「删除」一节）。
- 导入时 `setBoardInfo` 按 `sessions.boardId` 重算这两个字段，不再按卡片求和。

### 现状问题：一次专注被多张卡重复计入

番茄结束时 `Board/action.ts:511-525` 会把会话挂到 `focusedList` 里的**每一张**卡片，并给每张卡的 `spentTimeInHour.actual` 各加一次全额时长。`sessions` 仍只有一条，所以历史统计正确；但卡片时长失去「这张卡实际花了多少时间」的含义。

导入曾把这个问题放大：`setBoardInfo` 按卡片重算看板时长（`board.spentHours = Σ card.actual`），进行中有 N 张卡时，导出再导入会让看板总时长变成实际的 N 倍；未挂卡的会话则在每次导入时被直接抹掉。两端现在都改成按 `sessions.boardId` 重算。

### 一番茄一卡

规则：

- `focusedList` 恰好一张卡 → 不问，直接挂（与现有体验一致）。
- `focusedList` 多张卡 → 结束遮罩上出现「本次专注的卡片」选择器，默认第一张，可切换，也可选「不挂卡」。
- `focusedList` 为空 / 项目没有 focusedList → 不挂卡，进入「未分配番茄」。
- 一次番茄最多写入一张卡的 `sessionIds`，时长只累加一次。

#### 与遮罩上的项目选择共存

遮罩上已经有一个可编辑的项目选择（`SessionEndingMask` 的 `FocusSelector`，点击大标题进入编辑态），卡片选择必须和它共用同一套编辑态，不能各自占用点击区域。

非编辑态：

```
┌──────────────────────────────────────────────┐
│                  项目 A                      │  ← 点击进入编辑
│           卡片：写文档（3 张中）               │  ← 仅多卡时出现，点击同样进入编辑
│              Session Finished                │
│             [ 开始短休息 ]                    │
│           Today's Pomodoros ● ● ● ○          │
└──────────────────────────────────────────────┘
```

编辑态（点项目名或卡片行）：

```
┌──────────────────────────────────────────────┐
│              [ 项目 A        ▾ ]             │
│        本次专注  [ 写文档     ▾ ]            │  ← 仅多卡时出现
│                     [ 确认 ]                 │  ← 仅无项目（locked）时出现
│              Session Finished                │
│             [ 开始短休息 ]                    │
│           Today's Pomodoros ● ● ● ○          │
└──────────────────────────────────────────────┘
```

规则：

- 无项目（`needsProject`）时只显示项目选择器，不显示卡片行；选完项目后卡片行才出现。`locked` 与确认按钮只服务于「无项目」，与卡片无关。
- 卡片行只在当前项目的 `focusedList` 有 ≥ 2 张卡时出现；1 张时自动挂、不占位；0 张时不挂卡。
- 切换项目会重置卡片选择为目标项目的第一张可挂卡（或「不挂卡」），因为卡片属于列表，跨项目不成立。
- 点「确认」时同时快照 `boardId` 与 `cardId`，`onSessionConfirmed` 用快照写入，避免遮罩延迟关闭期间的选择变化。
- 卡片选择器复用「选择卡片」弹窗（按列表分栏，含「不挂卡」），不新增第三方下拉。
- compact 模式下非编辑态只显示卡片标题，编辑态仍可展开。

实现涉及：`SessionEndingMask` 的 `showPicker` / `editing` 扩展为同时控制两行；`FocusSelector` 过滤隐藏看板（已完成）；`Timer.onSessionConfirmed` 传单个 `cardId`；`actions.timerFinished`、`Board.onTimerFinished` 的 `cardIds: string[]` 改为 `cardId?: string`。

实现细节（第 3 步定稿）：

- 卡片选择弹窗落在 `src/renderer/components/Kanban/CardPicker.tsx`，按 `board.lists` 分栏，含「不挂卡」和「取消」，`zIndex` 默认 1100（结束遮罩是 z-index 1000 的 fixed 层）。它必须渲染在 `Mask` 的**兄弟位置**而不是内部：React portal 的事件仍沿 React 树冒泡，放在 `Mask` 内会让弹窗里的每次点击都触发遮罩自己的 `onCancel`，直接确认掉这次会话。
- 遮罩回调用 `string | null` 传卡：`null` 表示用户明确选了「不挂卡」，`undefined` 表示没有做出选择（例如托盘菜单、F5 这类没有卡片的确认路径）。`Timer.resolveCardId` 只在后者回退到 `defaultCardId`（`focusedList` 的第一张卡），所以「不挂卡」不会被默认值悄悄覆盖。
- 托盘菜单 / F5 / 背景点击在遮罩显示期间确认时，同样按「第一张卡」处理，与遮罩的默认选中保持一致。
- 遮罩打开或切换项目都会把卡片重置为目标项目的第一张卡；`focusedList` 里已被删除的卡（`kanban.cards` 里查不到）会被跳过，避免留下悬空引用。
- `Card.onTimerFinished` 仍是 `$push sessionIds + $inc actual`，但现在只会对一张卡调用。

WIP 限制（进行中列表最多几张卡）作为**独立的看板功能**后续单独做，默认不限，不影响番茄归属。不放在「设置-计时器」里。

### 按天管理弹窗（已定）

入口：History 点击某天 → 日期条上的番茄圆点旁「管理」。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 2026-11-11 的记录                                              [ × ] │
│                                                                      │
│ [ 全部 ] [ 未挂卡 ] [ 无项目 ]              已选 2 条                  │
├──────────────────────────────────────────────────────────────────────┤
│ ☐   ●  09:00  0.42h   项目 A          写文档 +1             [ 删除 ] │
│ ☑   ●  10:00  0.83h   项目 A          未挂卡                [ 删除 ] │
│ ☑   ●  14:00  0.42h   Unknown         未挂卡                [ 删除 ] │
├──────────────────────────────────────────────────────────────────────┤
│                                   [ 批量设置项目 ] [ 批量设置卡片 ]   │
│                                             [ 取消 ]  [ 保存 ]        │
└──────────────────────────────────────────────────────────────────────┘
```

交互规则：

- **圆点打开桑基图**：每行一个 `PomodoroNumView` 圆点（单条、`showNum={false}`、`inline`），点击 `setChosenRecord` 打开这一条会话的桑基图，与日期条上的圆点是同一个动作、同一个组件。它在勾选列的右边，与看板页「未分配番茄」弹窗同位置。

- **草稿 + 保存**：项目、卡片、删除全部先改本地状态，点「保存」才写库。删除点一次标记（行灰化 + 删除线），再点取消标记；保存时汇总「修改 N 条、删除 M 条」后一次提交。关闭时有未保存改动需确认丢弃。
- **改项目会清空该行的卡片**（原卡属于旧看板，不能跨板引用），卡片列变为「未挂卡」并提示「已解除原卡片关联」。批量设置项目同样清空所有选中行的卡片。
- **批量设置卡片要求选中记录同属一个项目**，跨项目时按钮置灰并提示。
- **卡片可退回未挂卡**：卡片选择弹窗提供「不挂卡」选项。
- 「卡片」列显示引用它的卡片标题，多张时「标题 +N」，没有则「未挂卡」。

实现细节（第 5 步定稿）：

- `SessionDayEditor`（`src/renderer/components/History/SessionDayEditor.tsx`）是 connected 组件，从 store 读 `kanban.boards` / `kanban.cards`；「管理」按钮挂在 History 选中日期的圆点旁，只在当天有记录时出现。
- 草稿里保存 `originalBoardId` / `originalCardIds`：保存时只有与原值不同的字段才进 `SessionEdit`，所以「没动过的行」不会把多卡引用悄悄收敛成一张。
- 改项目会把该行卡片清空（卡片属于看板，跨板不成立）；改回原项目时恢复原始卡片。
- 批量设置卡片要求选中记录的草稿项目一致且非空，否则按钮置灰并提示。
- 有未保存改动时关闭要经 `feedback.confirm` 二次确认；保存前汇总「修改 N 条 / 删除 M 条」再提交。
- 保存成功后 `History` bump `reloadToken`：聚合和「当天的记录」查询共用这个 token，两处一起刷新。
- **事务结果必须写回 store**：`applySessionEdits` 返回 `updatedCards` / `updatedBoards`，由 `applySessionEditsResult`（`Kanban/sessionEdits.ts`）在 cards / boards 两个 reducer 里整体替换。只写数据库不更新 store 时，项目列会因重新查询而正确，卡片列却要等应用重启——编辑器的卡片归属读的就是 `kanban.cards`。
- `History.test.tsx` 用 `jest.mock('./SessionDayEditor')` 挡掉这个 connected 子树（它需要 store，而 History 测试是裸渲染），编辑器的行为由自己的测试文件覆盖。

#### 弹窗里的桑基图

桑基图是 `Application` 里的一层全屏 fixed 覆盖（`Visualization/PomodoroSankey.tsx`），读的是 `state.timer.chosenRecord`，不归弹窗管理。在弹窗里打开它有三个坑：

- **层级**：全屏层原来是 `z-index: 500`，`AppModal` 的 wrap 是 1000，直接打开会被弹窗盖住。抬到 1050：高于所有弹窗，低于 picker 的 1100（图开着时打不开 picker，两者不会同时出现）。
- **Esc**：`Hotkeys` 在 antd 弹窗打开时整体停用（`popupLayer.isModalOpen` 那个 modal gate），桑基图若继续用它，图开着时 Esc 既不会关图，又会落到 rc-dialog 上关掉弹窗、弹出「丢弃改动」确认——一次按键两个后果。所以桑基图的 Esc 改成 document **捕获阶段**监听，先 `stopPropagation` 再关闭，一次 Esc 只关图。
- **数据**：历史页的记录是完整 `PomodoroRecord`（含 `apps` 明细），可以直接 `setChosenRecord`；未分配面板只有摘要，要先 `sessionDB.findOne` 取一条。缺 `stayTimeInSecond` 的旧记录由桑基图自己 toast「数据过旧」，弹窗不处理。

### 未挂卡会话的定位

判定：会话的 `_id` 不出现在任何 `card.sessionIds` 中。一个会话可能被多张卡引用（见上），判断的是「是否被至少一张卡引用」。

两个出口，不做首页角标：

**1. 按天弹窗**

- 每行增加「卡片」列：列出引用它的卡片标题（多张时显示前两张 + 「+N」），没有则显示「未挂卡」。
- 顶部增加归属筛选：「全部 / 未挂卡 / 无项目」。
- 数据来源：渲染层已有的 `kanban.cards`，构建一次 `Set<sessionId>`，不需要额外查询。

**2. 看板页「未分配番茄」弹窗**

- 入口：进入看板后，顶部工具栏右侧「未分配 N」按钮（N 为该板未挂卡会话数）。
- 点击打开弹窗（`AppModal`，不是 antd `Drawer`：弹窗与全应用其它对话框共用同一套无动效打开方式，软件渲染下不用为滑入动画重绘整窗）：

```
┌────────────────────────────────────────────────────────────────────────────┐
│ 未分配番茄 · 项目 A                                                  [ × ] │
│ 这些专注还没有关联到卡片                                                   │
│                                                                            │
│ [ 全选 ]   已选 2 条                                 [ 批量设置卡片 ]       │
├────────────────────────────────────────────────────────────────────────────┤
│ ☐    ●   11-11 09:00   0.42h   未挂卡                          [ 删除 ]    │
│ ☑    ●   11-10 15:00   0.83h   待办 › 写文档                   [ 删除 ]    │
│ ☑    ●   11-09 10:30   0.42h   未挂卡                          [ 删除 ]    │
│ …                                                                          │
├────────────────────────────────────────────────────────────────────────────┤
│                                                      [ 取消 ]  [ 保存 ]    │
└────────────────────────────────────────────────────────────────────────────┘
```

- 骨架与按天弹窗一致：同宽（`DAY_EDITOR_WIDTH` = 860）、同一套七列表格（勾选 / 圆点 / 时间 / 时长 / 卡片 / 删除），只是去掉项目列、项目筛选和「批量设置项目」——这个列表里的行本来就全是「有项目、未挂卡」。
- 圆点（`PomodoroNumView`，单条、`showNum={false}`、`inline`）打开这一条会话的桑基图，与历史页点圆点是同一个动作。
- 删除和其他编辑一样是草稿：点一次标记（行灰化 + 删除线），再点取消标记；`保存`把它和卡片改动一起提交为 `{ _id, delete: true }`。
- 有未保存改动（卡片或删除标记）时关闭要 `feedback.confirm` 二次确认；保存前汇总「修改 N 条、删除 M 条」。
- 行内「未挂卡」可点，打开同一个卡片选择弹窗（范围固定为本项目）。
- 不提供「跳到当天」（避免把 History 的日期状态提升成跨页状态）。
- 数据读取放在 `useUnassignedSessions(boardId)`（`Board/useUnassignedSessions.ts`），由 `Kanban` 调用：按钮的 N 和弹窗的列表来自同一次查询，弹窗本身是纯展示组件（`rows` / `total` 由 props 传入），保存成功后调 `onSaved` 重新读取。
- 桑基图要完整记录，摘要行不够：`useUnassignedSessions` 另暴露 `loadRecord(id)`，用 `sessionDB.findOne` 取一条再交给 `setChosenRecord`。`Kanban` 把 `chooseRecord` 注入面板。
- 保存失败时弹窗保持打开；`applySessionEdits` 的返回值经 `applyEdits` 写回 `kanban.cards`，看板上的卡片时长立刻更正。
- 数据来源：主进程新命令 `listUnassignedSessions(boardId, limit)`：
  1. 读 `cards.session_ids` 列构建 `Set`；
  2. 查 `sessions WHERE board_id = ?`；
  3. 做差集，返回轻量字段（`_id`、`startTime`、`spentTimeInHour`、`applications` 数量）与总数；
  4. 默认限制返回条数（如 200），总数单独给出，供「未分配 N」显示。

### 编辑提交（移动语义）

两个面板共用一条主进程事务命令，前端只提交差异，不逐条写库：

```
applySessionEdits([
  { _id, delete: true },
  { _id, boardId: 'x' },              // 改项目，自动解绑原卡
  { _id, boardId: 'x', cardId: 'c' }, // 同时挂卡，卡必须属于 x
  { _id, cardId: null },              // 取消挂卡
])
```

一个事务内按顺序执行：删除 → 解绑（项目变更或 `cardId: null`）→ 改 `boardId` → 挂卡 → 扣减/累加卡片 `actual` → 重算受影响看板汇总。任何一条校验失败整体回滚，弹窗保持打开。

规则：

1. **目标卡必须与会话最终的 `boardId` 属于同一看板**。挂卡不改变项目归属；无项目的会话必须先改项目才能挂卡。
2. **唯一归属**：挂到目标卡之前，先把该会话从其他所有卡片的 `sessionIds` 中移除，并按 `spentTimeInHour` 扣减那些卡片的 `actual`。保证一条会话最多只计一次卡片时长。
3. 目标卡已经有该会话时不做任何事（幂等）。
4. 卡片 `actual` 不做前端加减：主进程返回受影响卡片的新 `sessionIds` 与新 `actual`，渲染层整体覆盖，避免浮点漂移。
5. 看板级 `spentHours` / `relatedSessions` 按**会話**累加，与挂到哪张卡无关。因此：只换卡时看板汇总不动；改项目时旧看板要移除该会话并扣减时长、新看板加上；删除记录同理。
6. 删除记录也要先从所有卡片解绑并扣减 `actual`，否则卡片会引用一条已不存在的会话。
7. 保存成功后两处面板都要刷新：History 重新聚合（`reloadToken`），看板页重新拉 `listUnassignedSessions` 与「未分配 N」。

实现细节（第 4 步定稿）：

- 主进程序列：读 `cards` / `lists` / `boards` / 目标 `sessions` → 在事务外完成全部校验与草稿计算 → 开事务写入。校验失败时数据库和打开的弹窗都不动。
- 卡片的看板归属由 `board.lists → list.cards` 反查，卡片自身没有 `boardId`；跨看板挂卡、目标卡不存在、会话没有项目却要挂卡，都会整批拒绝。
- 同一张卡上的重复引用按出现次数各扣一次时长，存量脏数据不会留下虚高。
- `boardId: null` 用 `$unset` 写库（而不是 `$set null`）：历史与聚合都按「字段不存在」处理，避免出现 `boardId: null` 这种半合法值。
- `listUnassignedSessions` 走 `findHistory`，只取 `_id / startTime / spentTimeInHour / apps / boardId`。**`boardId` 必须出现在字段列表里**：`findHistory` 在最后还会用内存匹配器再过一遍投影后的文档，没选中的查询字段会让所有行被过滤掉。
- `listUnassignedSessions` 返回的总数是全量计数，`sessions` 只是按 `startTime` 倒序的前 `limit` 条（默认 200，上限 500）。

### 卡片跨看板移动

卡片没有 `boardId`，归属来自 `list.cards` → `board.lists`；而卡片里的每条会话有独立的 `boardId`。只改列表引用会让卡片在新看板、番茄仍归旧项目——历史页与看板的会话统计（`relatedSessions` / `spentHours`）都会把它们算在旧板上。因此**卡片移动时，它的番茄记录一起迁移项目**。

事务命令 `moveCardToBoard(cardId, targetListId)`：

1. 校验源列表、目标列表、源/目标看板；目标列表不能与源列表相同。
2. 从源 `list.cards` 移除，追加到目标 `list.cards` 末尾。
3. 写一条 `move` 记录（`fromListId → toListId`），保证导出再导入时 `cloneList` 不会把卡片放回旧列表。
4. 目标列表是目标看板的 `doneList` 时设置 `completedTime = now`（与拖拽语义一致）；移出 done 列表保留原值。
5. 对卡片里的每条会话：先从**其他卡片**的 `sessionIds` 解绑并扣减那些卡的 `actual`（唯一归属，与批量挂卡的移动语义一致），再把 `sessions.boardId` 改成目标看板。
6. 跨板时把每条会话从源看板的 `relatedSessions` / `spentHours` 移出，再累加到目标看板。
   **不做全量重算**：`spentHours` 是会话级汇总，按卡片求和会把「有项目但没挂卡」的会话时长抹掉（与删除路径同一条原则）。
7. 返回受影响的卡片与看板最终状态，渲染层整体覆盖。

UI：

- 入口：卡片编辑弹窗底部「移动到…」，与「删除」并列。
- 两步共用一个弹窗，只换内容区，不「关一个开一个」——理由见下。
- 第一步是「选择项目」内容（含搜索、排序、隐藏标记）。
- 第二步是「选择目标列表」内容：把该项目的列表横向排列，标出 `focused` 与 `done`，默认选中目标看板的 `focusedList`；没有 focusedList 时选第一个列表。

```
┌──────────────────────────────────────────────────────┐
│ 移动到 · 项目 B                                [ × ] │
│ [ 待办 ]  [ 进行中 ★ ]  [ 完成 ✓ ]  [ 归档 ]         │
│ 该卡片的 3 个番茄记录会一并移到项目 B                  │
│ 其中 1 条同时属于其他卡片，将先从那些卡片移出          │
│                              [ 取消 ]   [ 移动 ]     │
└──────────────────────────────────────────────────────┘
```

边界：

- 同看板换列表也走这条路径，等价于拖拽但多一层确认。
- 目标看板是隐藏板时标注「已隐藏」，仍可选（与项目选择弹窗一致）。
- 批量移动暂不做，命令按单卡设计；后续接多选时扩展入参即可。
- 移动不可撤销，确认框要写明会话会跟随迁移。

#### 两步为什么共用一个弹窗

两个独立弹窗接力时，切换会闪一下：背景暗一下，不是内容跳。

原因是 `open` 的两次变化落在同一次 commit 里：旧弹窗 `open=false`、新弹窗 `open=true`。rc-motion 的 leave 分 prepare 与 active 两阶段，`-leave-active` 要等下一帧才加上，`animationend` 后再一帧才把 portal 设成 `display: none`。于是**新弹窗的遮罩已经完全不透明时，旧遮罩还在**，0.45 叠 0.45 约等于 0.70，背景先变深再落回来。底下 `CardEditor` 自己那层 1000 的遮罩也开着，实际是三片变两片。前进和取消各触发一次，不是首次才有的问题。

所以两步共用**一个** `AppModal`：标题、按钮随 `step` 变，内容区在 `ProjectPickerBody` 与 `ListPickerBody` 之间切换。遮罩只挂一次、卸载也一次；body 换掉时它的内部状态（搜索词、排序、选中列表）跟着卸载自然重置，不需要再写 `useEffect` 清空。

两个推论：

- 两个 body 必须同高（`PICKER_BODY_HEIGHT` = 380）。否则合并后 Modal 在两步之间改高度，底部塌一下，还是「窗口在跳」。现在 `ListPicker` 按内容撑高，实际只有 140 左右，是唯一没接这个常量的选择器，合并时一并补上。
- 底部按钮放进 body 自己的一行，`AppModal` 传 `footer={null}`。第二步的确认按钮要读 body 内的选中列表；footer 若由 Modal 渲染，就得把选中态提升到容器，父子两边各推一次默认列表，两处逻辑迟早会分叉。代价是 `ProjectPicker` 的「取消」从 Modal footer 挪进 body，视觉上要自己补上 `margin-top` 与右对齐。

实现细节（第 7 步定稿）：

- 主进程命令在 `src/main/db/cardMove.ts`，返回 `updatedCards` / `updatedLists` / `updatedBoards`（`src/shared/cardMove.ts`）；渲染层 `applyCardMove`（`Kanban/cardMove.ts`）在 cards / lists / boards 三个 reducer 里整体替换，和删除、会话编辑同一套「事务返回终态」的写法。
- 卡片没有 `boardId`，跨板判断按**每条会话自己的 `boardId`** 做，而不是看卡片原来的看板：存量脏数据里会话可能已经指向别处，按会话判断才能让源看板的扣减落在正确的板上。
- 卡片同时出现在多个列表（旧数据）时，从所有源列表移除，`move` 记录的 `fromListId` 取第一个；不在任何列表的孤儿卡不写 `move` 记录（没有旧位置需要压住），仍然可以移动。
- `completedTime` 只在目标列表是该看板的 `doneList` 时写 `Date.now()`；离开 done 列表保留原值，与拖拽一致。
- 会话解绑其他卡片时按出现次数扣减，和 `applySessionEdits` 一样，存量重复引用不会留下虚高。
- UI 是两步：`BoardListPicker`（`Kanban/BoardListPicker.tsx`）包一个 `AppModal`，`step === 'project'` 时渲染 `ProjectPickerBody`（`allowNone={false}`，移动必须有目标板），否则渲染 `ListPickerBody`（标出 `focused` / `done`，默认选 `focusedList`，源列表禁用）。第二步的「取消」回到项目步，不是关闭整个流程。`RestoreCardsDialog` 用同一个 `BoardListPicker`，只换确认文案与回调。
- `ProjectPicker` / `ListPicker` 的内容拆成具名导出 `ProjectPickerBody` / `ListPickerBody`，两者都用 `PICKER_BODY_HEIGHT` 固定内容高度，并自带一行底部按钮。`ProjectPicker` 仍是 `AppModal + ProjectPickerBody`（按天弹窗在用）；`ListPicker` 组件随两个调用点改用 `BoardListPicker` 而删除。
- 入口在 `CardEditor` 底部与「删除」并列，仅编辑态显示；`CardMoveDialog`（`Kanban/CardMoveDialog.tsx`）自己 connect，避免把整张 `cards` / `lists` 表塞进重量级的卡片编辑弹窗。
- 卡片编辑弹窗的 document 级 Esc/Ctrl+Enter 监听要把 `moveOpen` 一起排除，否则在移动弹窗里按 Esc 会关掉背后的编辑器并丢掉未保存内容（与插入链接弹窗同一处理）。

### 拖动事务化

跨列表拖动原来是渲染层的三次独立写（源列表、目标列表、`move` 记录）。中途崩溃或强退会留下既不在源列表、也不在目标列表的卡片，也就是检查弹窗里「不属于任何列表」那一栏。

现在走主进程 `moveCardInBoard`（`src/shared/cardDrag.ts` + `src/main/db/cardDrag.ts`），一个事务完成：

- 输入 `cardId`、`fromListId`、`toListId`、`toIndex`；`toIndex` 是拖拽库报告的「移除后插入位置」，越界收敛到 `[0, length]`。
- 同列表只重排：不写 `move`、不盖 `completedTime`。跨列表写一条 `move`，目标列表是该看板 `doneList` 时盖 `completedTime`，移出保留原值。
- 两个列表必须属于同一看板（拖拽上下文只覆盖一个板）；只有一方能解析到看板时（旧数据里列表不在任何看板）允许通过，避免用户拖不动。
- 渲染层先乐观更新（与原来同一套 reducer 逻辑），成功后用事务返回的 `updatedLists` / `updatedCards` 整体覆盖；失败时重新拉取列表并 toast，不做反向拼接。
- 索引解析 `resolveDragIndexes` 由 reducer 与 thunk 共用：搜索过滤下的可见索引到这里一次换算，两边用同一个结果，避免屏幕和数据库各选一张卡。
- `Board.onCardMovedInto` 删除：`completedTime` 已由事务写，不再需要渲染层二次请求。

### 番茄结束的写入

番茄结束原来是三次独立写：`addSession` 插会话、看板 `$push relatedSessions` + `$inc spentHours`、卡片 `$push sessionIds` + `$inc actual`。而 `addSession` 自己的 `.catch(console.error)` 把插入失败吞掉了，`timerFinished` 仍然继续挂卡——卡片于是指向一条不存在的会话，正是「有 sessionId 没有记录」。

现在走主进程 `recordFinishedSession`（`src/shared/finishedSession.ts` + `src/main/db/finishedSession.ts`），一个事务完成：

- 入参只有 `session` 与 `cardId`。看板归属取 `session.boardId`，`timerFinished` 的第三个参数随之删除——会话自己的 `boardId` 就是历史页判断项目的那一列，多传一份只会让两者有机会不一致。
- 顺序固定：先插会话行，成功后再写看板与卡片。任何一步失败都整笔回滚，不会出现「看板时长加了、会话没写进去」。
- 看板或卡片在专注期间被删掉时跳过对应的更新，会话照常落库并保留悬空的 `boardId`：历史页显示 `Unknown`，之后可以在会话编辑里重新分配。丢番茄记录比留一条未归属记录严重得多。
- 重复 `_id` 直接拒绝（`session ... already exists`），重放不会把看板时长和卡片时长加两遍。
- `relatedSessions` / `sessionIds` 用「过滤后追加」而不是 `$push`，同一个 id 不会被记两次；时长累加后过 `roundHours`，与删除、移动的精度一致。
- 渲染层 `applyFinishedSession`（`Kanban/finishedSession.ts`）在 boards / cards 两个 reducer 里整体替换事务返回的行。写失败时不 dispatch，store 里不会留下乐观的小时数；同时 toast `timer.saveFailed`，主进程把失败写进 `data.log`。
- `Board.onTimerFinished`、`Card.onTimerFinished`、`Card.addSession` 一并删除，`sessionManager.addSession` 不再吞错（保留给只写会话行的调用方）。

之所以不满足于「插会话失败就跳过挂卡」：反方向的半套状态同样会发生——看板写完、卡片没写，或者两个都写了、会话没写。只有把四步放进同一个事务，两个方向才都关掉。

## 检查与修复数据

设置 → 系统 → 数据管理新增「检查并修复数据」。它不再是一键删除：扫描结果按表分成卡片、列表、移动记录三组，另加一组悬空引用；用户逐项勾选后处理，卡片还可以恢复到指定列表。

扫描口径：

- **卡片**，组内按来源分两栏：
  - 「来自已删除的看板 / 列表」：仍被某个孤儿列表引用。孤儿列表指没有任何 `board.lists` 引用的列表，也就是旧版「只删看板行」留下的整棵子树。用户当初就想删掉这些内容，默认勾选。
  - 「不属于任何列表」：不被任何列表引用。来源更可能是跨列表拖动时崩溃、导入合并丢弃归属、或手工改过的 JSON。默认不勾选，主要靠「恢复」处理。
  - 两栏都显示卡片标题，附原列表名（如果有）、已记录时长与番茄数——这是唯一有可能被误删的类别，必须有可读内容。
- **列表**：没有任何 `board.lists` 引用的列表。只显示标题，不显示卡片数（会让人以为一并删卡）；原看板名随看板删除而不可恢复，表头统一说明。默认勾选。
- **移动记录**：`cardId` 或两个端点列表已不存在的行。没有用户可读的内容，只显示条数与涉及的卡片数。默认勾选。
- **悬空引用**：`board.lists` 里的死列表 id、`list.cards` 里的死卡片 id、`card.sessionIds` 里的死会话 id，以及同名数组里的重复 id。按 owner 聚合，每条写明修复只移除引用，不删除卡片、列表或番茄记录。默认勾选。
  owner 行下逐行列出会被移除的 id（死行已经没有名字，id 是唯一可查的标识），重复出现合并成 `id ×N`；owner 行尾附上它自己的 id，因为「待办」这类名字会重名。每个 owner 默认显示 5 个 id，超出显示「显示更多（还有 N 个）」，点一次展开该 owner 的全部。

交互：

- 空组隐藏；四组全空时不打开弹窗，只提示「没有发现问题」。
- 一个主按钮「处理选中项 (N)」：点它先弹出**确认窗口**，只显示选中项的分类计数（卡片 N 张、列表 N 个、移动记录 N 条、引用 N 处），标题写明「处理这些数据问题？」。
  确认后才执行，一次事务同时删除勾选行并修复勾选的引用。**一律弹确认**，即使只勾选了引用修复——「处理」这个词覆盖太广，确认窗口负责说清这次到底做什么。
- 「恢复选中 (N)」放在卡片组的标题行，而不是弹窗底部：底部按钮容易被读成「恢复所有问题」，而它只作用于卡片；一次把选中的卡片放进同一个列表（先选看板，再选列表）。
- 恢复走 `moveCardToBoard`，不是往 `list.cards` 里塞 id：卡片里的会话有自己的 `boardId`，只改引用会出现「卡片在新看板、番茄算旧项目」，恢复后历史里的 `Unknown` 也不会消失。两步选择用和「移动到…」同一个 `BoardListPicker`，只换确认按钮文案。
- 处理或恢复后重新扫描，弹窗保持打开；全部清空后显示空状态。
- 卡片和列表的每一行显示短 id（放在标题后的信息行里），便于排查；确认窗口只给计数，不再列 id。
- 每组最多渲染 50 条，末尾一个「显示全部（还有 N 条）」按钮，点一次展开该组全部条目；全选与处理始终作用于全部，不受渲染上限影响。这是 owner 行数的上限，与每条悬空引用自己的 id 折叠（5 条）相互独立。
- 处理完成后只 toast 汇总「删除 X 张卡片、Y 个列表、Z 条移动记录，修复 N 处引用」。


实现细节（第 8 步定稿）：

- 主进程拆成 `scanDataIssues()` 与 `repairData(payload)`（`src/shared/dataRepair.ts` + `src/main/db/dataRepair.ts`），类型是 `DataIssuesReport` / `DataRepairPayload` / `DataRepairResult`。扫描只读，修复在弹窗提交后重新读库。两次调用之间隔着弹窗，期间新结束的番茄会挂到卡片上，用扫描时的旧快照去删就会误删。
- 「被引用」只算**处理后仍存活**的列表：孤儿列表里的 `cards` 不算引用。否则孤儿列表被删掉后，它独有的卡片要等下一次扫描才会被清走，用户会看到「处理了但还有」。
- 移动记录的数量按**当前**状态统计（指向已不存在的卡片或列表），删除时按**处理之后**的存活集合计算 `$nin`，所以一次处理能清干净；只删卡片而不勾移动记录时，新变成死记录的 move 会在下一轮出现。
- 孤儿列表里的卡片若同时被有效列表引用，删列表不删卡。因此不复用 `deleteKanbanItems`——它的级联规则是「删列表必删卡」。
- `moves` 表没有 `_id`（`moveSpec.hasId === false`），无法按行标识删除；清理条件写成 `$or: [cardId $nin 存活卡, fromListId $nin 存活列表, toListId $nin 存活列表]`，与扫描用的是同一组集合。
- 删除不动 `sessions` 和看板汇总：看板按会话统计，删卡只让这些会话变成「未挂卡」。
- 设置页只负责「扫描 → 打开弹窗」，弹窗自己调用 `repairData` 并通过 `applyRepair` 把结果写回 store（`applyDataRepair` 在 cards / lists / boards 三个 reducer 里整体替换 `removedCards` / `removedLists` / `updatedCards` / `updatedLists` / `updatedBoards`）。
- 删除一张卡片时，同时从所有列表的 `cards` 里移除它；删除一个列表时，同时从所有看板的 `lists` 里移除它。否则「删卡」会当场制造一条悬空引用，和这次修复的目标相反。
- `DanglingRefIssue.ids` 是去重后的 `{ id, times }` 列表：`times` 是该 id 在数组里的总出现次数，`count` 是会被删掉的条目数。死 id 出现三次 → 一行 `×3`、`count = 3`；有效 id 出现两次 → 一行 `×2`、`count = 1`（只删第二份）。顺序按首次出现，与数组顺序一致。
- 扫描与修复只读需要的列。`findSync` 会把每行的 `doc` 列整段 `JSON.parse`，而 sessions 的 `doc` 带着每个应用/标题的明细：2 万条会话实测一次扫描 **1033 ms**，主进程的单线程被占满约一秒，窗口连重绘都停下，用户看到的就是「点击后卡住 → 才出现转圈 → 再出现面板」。改用 `idsSync()`（只 `SELECT _id`）与 `findFieldsSync()`（只 `SELECT` 需要的列，只解析选中的 JSON 列）后，同一数据量 **13 ms**，点击立刻得到转圈。
  `repairData` 同样处理：会话只取 id；卡片只有被勾选修复 `sessionIds` 的那几张取完整行（要整体写回 store），其余只取 id。`findSync` 保留给事务里确实需要整行的调用。

## 边界与风险

- 删除不可恢复，没有回收站。
- 删看板后 `sessions.boardId` 悬空，导入日志的 `unknown=N` 会增加；这是预期结果。
- 隐藏板仍在 `boards` 表，不算 `Unknown`。
- 番茄会话可能被多张卡引用，卡片时长因此可能重复计算（现状，本设计对**新数据**改为一番茄一卡；存量数据不会自动收敛）。
  这只影响卡片自己的时长和剩余估算；`board.spentHours` 按会话统计，不受多卡引用影响。
  存量处理需要单独决定「同一会话被多卡引用时保留哪一张」，暂不纳入本设计。
- 项目聚焦但没有卡片时产生的会话，属于正常状态而非错误，UI 不要用警告色。
- **旧版本的导入不是事务**（v0.7.1 的 `writeAllFile` 先清空五张表，再 `Promise.all` 并发插入）。中途失败或崩溃会留下「卡片有 `sessionIds`、会话表却是空的」这种半套数据，也就是「有 sessionId 没有记录」。当前导入已改成单事务（`src/main/io/write.ts`），这类数据只能靠检查弹窗发现。
- **番茄结束时的会话写入已改为单事务**（第 10 步）：`recordFinishedSession` 先插会话，再写看板与卡片，失败整笔回滚并 toast。旧的 `addSession(...).catch(console.error)` 会吞掉错误后继续挂卡，这也曾是「有 sessionId 没有记录」的另一条来源。

## 测试

- 事务级联：删卡片/列表/看板后，`cards`、`lists`、`boards`、`moves` 无残留，`sessions` 不变。
- 删卡片/删列表不改变 `spentHours` / `relatedSessions`：会话仍属于这个项目，只是没有卡片了。
- 总览卡片与表格的「已花时间」等于 `board.spentHours`，未挂卡会话的时长也计入；剩余估算仍按卡片求和。
- `hidden`：筛选、聚焦下拉过滤、导出导入携带、合并时保留本地值。
- 改项目 / 删记录的自动解绑与看板汇总重算。
- 一番茄一卡：单卡时自动挂、多卡时选卡、选「不挂卡」时不写 `sessionIds`；任何情况下只改一张卡的 `actual`。
- 导入重算后 `board.spentHours` 等于该板各会话 `spentTimeInHour` 之和、`relatedSessions` 等于这些会话的 id，未挂卡的会话同样计入（不再按卡片求和，也不再出现 N 倍或被抹掉）。
- 未挂卡判定：被多张卡引用的会话不算未挂卡；从所有卡解绑后立刻算未挂卡。
- `listUnassignedSessions`：总数与分页数一致，隐藏看板不影响该查询。
- `applySessionEdits`：移动语义下旧卡 `actual` 扣减、新卡累加、旧卡 `sessionIds` 移除；重复调用幂等；禁止跨看板挂卡。
- 改项目时看板汇总跟着走（旧板移除并扣减、新板加上）；只换卡时看板汇总不变；删除记录会先从卡片解绑并更新看板；同一张卡上的重复引用按次数扣减。
- `listUnassignedSessions` 的 `boardId` 过滤有效（依赖把 `boardId` 选进 `findHistory` 的字段列表）。
- 草稿语义：删除标记可撤销；未保存时关闭需确认；保存一次提交全部变更，任一校验失败整体回滚。
- 未分配弹窗：行内改卡与删除标记都只在保存时提交；有改动时关闭要确认；「全选」只选未标记删除的行；点圆点用一条完整记录调 `chooseRecord`（摘要行不够），拿不到记录时给出提示而不是静默失败。
- 桑基图覆盖层：`z-index` 高于 `AppModal`（1050）；Esc 在捕获阶段处理并 `stopPropagation`，按一次只关图，不会顺带触发弹窗的未保存确认。
- 改项目会清空该行卡片；跨项目的批量设置卡片被禁用；`cardId: null` 能退回未挂卡。
- `moveCardToBoard`：源/目标列表引用正确、写了一条 move、会话 boardId 跟随、源/目标看板汇总重算、多卡共享时旧卡 `actual` 扣减、移入 done 列表设置 `completedTime`。
- 移动后导出再导入，卡片仍在目标列表（依赖 move 记录），会话仍归目标看板。
- 导入日志：清理后的数据不再产生 `moveDropped` / `cardRemoved`。
- `scanDataIssues`：被孤儿列表引用的卡片进 `detachedCards`、其余进 `orphanCards`；被有效列表引用的卡片两边都不进；move 计数与卡片数；三类悬空引用各自计数，重复 id 也算一处。
- `repairData`：只处理 payload 里的行（未勾选的孤立卡与死引用保持原样）；删卡时从所有列表移除该 id；删列表时从所有看板移除该 id；删除后再扫为空；删除不动 `sessions` 与看板汇总。
- 弹窗：默认勾选残留卡/列表/move/悬空引用，不勾孤立卡；payload 只含勾选项；行内与批量恢复都打开恢复流程；空报告显示空状态。
- 设置页：空报告只 toast；有报告打开弹窗；`applyRepair` 写回 store；恢复/处理后重新扫描。
- `recordFinishedSession`：会话、看板 `relatedSessions` / `spentHours` / `lastVisitTime`、卡片 `sessionIds` / `actual` 一起落库；无卡、无项目、看板被删、卡片被删都各有一条；重复 `_id` 拒绝；插入失败时看板与卡片不被记账；小时数按 `roundHours` 收敛。
- `timerFinished`：成功时把事务返回的行写回 store；失败时不产生 `applyFinishedSession`、toast 提示，且会话、看板、卡片都没有变化。
- `ProjectPicker`：默认创建时间新到旧、搜索忽略大小写、隐藏板有标记且仍可选、`allowNone={false}` 时没有「无项目」。
- `CardPicker`：按看板列表分栏、空列表不占一栏、无标题卡显示占位、底栏「不挂卡」。
- `CardMoveDialog` / `RestoreCardsDialog`：两步流程、成功后关闭并回调、失败时停留在弹窗；恢复批量在部分失败时只把真正恢复成功的卡片交回调用方。
- 两步共用一个弹窗：在项目步与列表步之间来回切换时，页面上的 `role="dialog"` 始终只有一个。两个弹窗接力会让两片遮罩重叠一帧，背景暗一下；这条断言就是压住那个回归的手段，注释里写清原因，不是单纯数 DOM。
- 从列表步回到项目步再选另一个看板时，列表选中重置为新看板的默认项（`focusedList`，否则第一个可用列表）；body 卸载重挂就该是这个结果，不需要手动清空。
- i18n：新增文案在 `en.ts` / `zh.ts` 成对存在（类型强制）；历史页的项目名在项目被删后显示本地化的「未知项目」，且该字符串不进缓存，切换语言后不会残留旧语言。
