# 国际化

应用同时提供英文（`en`）和简体中文（`zh`）。
这里没有 i18n 库：一个小小的自研 translator 让渲染层不需要 Provider（有 Provider 会让大量裸写的 `render(<Component />)` 测试无法工作），同时让语言切换能够重渲染那些被 `React.memo` 包住、或者自己实现了 `shouldComponentUpdate` 的组件。

## 各部分在哪

| 路径 | 作用 |
| --- | --- |
| `src/shared/i18n/en.ts` | **唯一事实来源**：key 树、插值签名和英文文案 |
| `src/shared/i18n/zh.ts` | 类型为 `CatalogShape<typeof en>`；缺 key、多 key 或参数表不一致都会让 `pnpm typecheck` 失败 |
| `src/shared/i18n/keys.ts` | `MessageKey`、`PlainMessageKey`、`MessageArgs`、`TranslateFn`，全部从 `en` 推导 |
| `src/shared/i18n/translate.ts` | `createTranslator(language)`；找不到 key 时返回 key 本身（不写日志，`test/console-gate.js` 把 `console.warn` 当作失败） |
| `src/shared/i18n/language.ts` | `languageFromLocale`、`resolveLanguage`、`isLanguagePreference` |
| `src/renderer/i18n/runtime.ts` | 模块级当前语言、`t()`、`subscribeLanguage`、`SYSTEM_LANGUAGE` |
| `src/renderer/i18n/hooks.ts` | `useI18n()`（`useSyncExternalStore`）/ `useTranslate()` |
| `src/renderer/i18n/live.ts` | 给 `FEEDBACK_MESSAGES` 用的 `liveMessages()` 代理 |
| `src/main/i18n.ts` | 主进程自己的那份：`getMainLanguage`、`setMainLanguage`、`m()` |
| `src/main/ipc/initialLanguage.ts` | 首次绘制用的 `--pl-initial-language=` 交接 |

## 怎么用

- **函数组件**：`const { t } = useI18n();` 然后 `t('key')`。
  这个 hook 保证即使父组件被 `React.memo` 拦下，语言切换时该组件仍会重渲染。
- **类组件、模块级工具函数、事件回调**：`import { t }`（来自 `renderer/i18n`），在产出文案的位置调用。
  它在调用时解析，所以托盘标签和通知正文跟随语言切换，不用改调用点。
- **常量表**：存 `PlainMessageKey`，不要存文案。
  `SECTIONS[].titleKey`、`APP_TABS[].titleKey`、`SHORTCUTS[].descriptionKey`、`GridCalendar.MONTH_KEYS` 以及 `FocusStartWarning.titleKey/contentKey` 都是这个模式。
  不要在模块作用域写 `const label = t('...')`：那会把 import 时生效的语言冻住。
- **主进程**：`import { m } from './i18n'`，在用的地方调用 `m('native.…')`。
- **插值**：英文值写成函数；参数类型就成为中文词条表必须满足的契约。
  `finishTooEarly: (minMinutes: number) => ...` → `t('...', 10)`。

## 语言状态

`timer.language`（`LanguagePreference` = `'system' | 'en' | 'zh'`，默认 `'system'`）放在已有的 Redux `timer` slice 里，与 `themeId` 相邻：

- `store/index.ts` 用 `window.api.initialLanguage` 给它做初值，并订阅 `setActiveLanguage(resolveLanguage(...))`，所以紧接着的那一次渲染就是正确语言（放在 effect 里会先画出一次旧语言）。
- 设置页（System 区）提供 *跟随系统 / 简体中文 / English* 三态。
  之所以是三态，是因为用户显式选过之后，「回到跟随系统」必须仍然可选。
- 选择结果以 `language` 存进 `settings` 表；老版本安装没有这个键，保持 `'system'` 默认值即可。

## 首次绘制

`init.ts` 的 `readInitialSettings()` 在窗口创建前读一次 SQLite，把 `--pl-initial-theme=` 和 `--pl-initial-language=` 一起经由 `webPreferences.additionalArguments` 传进去。
preload 把它们暴露为 `window.api.initialTheme` / `window.api.initialLanguage`；store 在首次渲染前 dispatch 它们，`app.tsx` 在 `applyTheme()` 旁边调用 `applyDocumentLanguage()`。

`<html lang>` 不是可选项：在某些 Windows 字体配置下，`lang="en"` 会让 Chromium 用日文字形来渲染中文。

## 必须同步维护的地方

- `Setting.tsx` 的 `settingUiStates` 和 `Timer/action.ts` 的 `uiStateNames`——那是 `React.memo` / `shouldComponentUpdate` 的白名单，两处都包含 `language`。
- `Timer.tsx` 的 `trayStateKeys`——托盘菜单靠它重建。
- 渲染层通过 `IpcEventName.SetLanguage`（`LanguageController`）通知主进程，主进程据此更新 `m()`、窗口标题，并用 `lastTrayItems` 重建托盘。
- `Application.tsx` 把 `antd/locale/{en_US,zh_CN}` 传给根 `ConfigProvider`；`LanguageController` 负责切换 `dayjs.locale`。

## 有意不翻译的内容

- **持久化的用户数据**：看板 / 列表 / 卡片 / 标签名称，以及新建看板时写入的默认列表名（`Backlog`、`TODO`……）。
  这些名字按创建时生效的语言写入，之后永不改写。
- **`defaultState.distractingList`**（`微博`、`哔哩哔哩`、`邮件`）：这是匹配模式，不是文案。
- **`TimeTreemap` 里的图表系列标识**（`PROJECT_SERIES_NAME`、`APPLICATION_SERIES_NAME`、`APPLICATIONS_OTHER_NAME`）：图表内部按值比较，测试也按值比对。
  它们的面板标题**是**翻译的。
- **排序**：`Overview.tsx` 里用 `new Intl.Collator('zh-Hans-CN')` 按拼音排列用户数据，与界面语言无关。
- **主进程的日志与开发者错误**。

## 测试

`test/setup-env.js` 把 `navigator.language` 钉在 `en-US`，`test/i18n.ts` 在每个测试后把当前语言重置为 `en`，所以现有的英文断言可以继续工作。
`src/shared/i18n/catalog.test.ts` 校验 key 对齐、叶子类型和非空值；`src/renderer/i18n/runtime.test.ts` 覆盖订阅与插值；`src/main/ipc/initialLanguage.test.ts` 覆盖启动参数。
