# Internationalization

The app ships English (`en`) and Simplified Chinese (`zh`). There is no i18n
library: a small custom translator keeps the renderer free of a provider (which
would break the many bare `render(<Component />)` tests) and lets a language
switch re-render components that are wrapped in `React.memo` or own a
`shouldComponentUpdate`.

## Where the pieces live

| Path | Role |
| --- | --- |
| `src/shared/i18n/en.ts` | **Source of truth**: the key tree, the interpolation signatures and the English copy |
| `src/shared/i18n/zh.ts` | Typed as `CatalogShape<typeof en>`; a missing key, an extra key or a different parameter list is a `pnpm typecheck` error |
| `src/shared/i18n/keys.ts` | `MessageKey`, `PlainMessageKey`, `MessageArgs`, `TranslateFn`, all derived from `en` |
| `src/shared/i18n/translate.ts` | `createTranslator(language)`; a missing key returns the key itself (never logs, `test/console-gate.js` treats `console.warn` as a failure) |
| `src/shared/i18n/language.ts` | `languageFromLocale`, `resolveLanguage`, `isLanguagePreference` |
| `src/renderer/i18n/runtime.ts` | Module level active language, `t()`, `subscribeLanguage`, `SYSTEM_LANGUAGE` |
| `src/renderer/i18n/hooks.ts` | `useI18n()` (`useSyncExternalStore`) / `useTranslate()` |
| `src/renderer/i18n/live.ts` | `liveMessages()` proxy used by `FEEDBACK_MESSAGES` |
| `src/main/i18n.ts` | The main process' own copy: `getMainLanguage`, `setMainLanguage`, `m()` |
| `src/main/ipc/initialLanguage.ts` | `--pl-initial-language=` hand-over for the first paint |

## How to use it

- **Function components**: `const { t } = useI18n();` then `t('key')`. The hook
  makes the component re-render on a language switch even when a parent bails
  out through `React.memo`.
- **Class components, module level helpers, event callbacks**: `import { t }`
  from `renderer/i18n` and call it where the text is produced. It resolves at
  call time, so tray labels and notification bodies follow a switch without
  touching their call sites.
- **Constant tables**: store `PlainMessageKey`, not text.
  `SECTIONS[].titleKey`, `APP_TABS[].titleKey`, `SHORTCUTS[].descriptionKey`,
  `GridCalendar.MONTH_KEYS` and `FocusStartWarning.titleKey/contentKey` are all
  this pattern. Never write `const label = t('...')` at module scope: it would
  freeze the language that was active at import time.
- **Main process**: `import { m } from './i18n'` and call `m('native.…')` at the
  point of use.
- **Interpolation**: write the English value as a function; the parameter types
  become the contract the Chinese catalog must satisfy.
  `finishTooEarly: (minMinutes: number) => ...` → `t('...', 10)`.

## Language state

`timer.language` (`LanguagePreference` = `'system' | 'en' | 'zh'`, default
`'system'`) lives in the existing Redux `timer` slice next to `themeId`:

- `store/index.ts` seeds it from `window.api.initialLanguage` and subscribes
  `setActiveLanguage(resolveLanguage(...))`, so the runtime is correct during
  the very next render (an effect would paint one frame of the old language).
- The settings page (System section) offers *Follow system / 简体中文 /
  English*. Three states, because "back to following the OS" has to stay
  reachable after an explicit choice.
- The choice is persisted in the `settings` table as `language`; older installs
  have no such key and simply keep the `'system'` default.

## First paint

`init.ts readInitialSettings()` reads SQLite once, before the window exists, and
passes both `--pl-initial-theme=` and `--pl-initial-language=` through
`webPreferences.additionalArguments`. The preload exposes them as
`window.api.initialTheme` / `window.api.initialLanguage`; the store dispatches
them before the first render and `app.tsx` calls `applyDocumentLanguage()` next
to `applyTheme()`.

`<html lang>` matters: with `lang="en"` Chromium may render Chinese with
Japanese glyph variants on some Windows font setups.

## Things that must be kept in sync

- `Setting.tsx` `settingUiStates` and `Timer/action.ts` `uiStateNames` — the
  `React.memo` / `shouldComponentUpdate` whitelists; both contain `language`.
- `Timer.tsx` `trayStateKeys` — the tray menu is rebuilt through it.
- The renderer tells the main process through `IpcEventName.SetLanguage`
  (`LanguageController`), which updates `m()`, the window title and rebuilds the
  tray from `lastTrayItems`.
- `Application.tsx` passes `antd/locale/{en_US,zh_CN}` to the root
  `ConfigProvider`; `LanguageController` switches `dayjs.locale`.

## Deliberately not translated

- **Persisted user data**: board/list/card/label names, and the default list
  names written when a board is created (`Backlog`, `TODO`, …). The names are
  written in the language active at creation time and are never rewritten.
- **`defaultState.distractingList`** (`微博`, `哔哩哔哩`, `邮件`): these are
  matching patterns, not copy.
- **Chart series identifiers** in `TimeTreemap` (`PROJECT_SERIES_NAME`,
  `APPLICATION_SERIES_NAME`, `APPLICATIONS_OTHER_NAME`): they are compared by
  value inside the chart and by the tests. Their panel titles *are* translated.
- **Sorting**: `new Intl.Collator('zh-Hans-CN')` in `Overview.tsx` orders user
  data by pinyin regardless of the UI language.
- **Logs and developer errors** in the main process.

## Tests

`test/setup-env.js` pins `navigator.language` to `en-US`, and `test/i18n.ts`
resets the active language to `en` after every test, so the existing English
assertions keep working. `src/shared/i18n/catalog.test.ts` enforces key parity,
leaf kinds and non-empty values; `src/renderer/i18n/runtime.test.ts` covers
subscription and interpolation; `src/main/ipc/initialLanguage.test.ts` covers
the startup argument.
